## Phase 5: 分层记忆系统 V1

### 概述

构建基于向量数据库的分层记忆系统，实现角色的长期记忆能力。

### 技术实现

- **记忆管理器**: [vdb_tools/hierarchical_memory_db.py](file:///d:/Data/PYC/LLMRolePlay/project_version_3.2.6_workspace/vdb_tools/hierarchical_memory_db.py) 中的 `HierarchicalMemoryManager` 类
- **向量数据库**: 集成 ChromaDB 0.4.18，按时间分区存储
- **嵌入模型**: 加载 BAAI/bge-large-zh-v1.5 模型（约 1.5GB），用于文本向量化
- **原始记录存储**: `raw_records/` 按半年分区存储原始对话记录
- **日级总结**: `summary_L1_daily/` 按日存储对话压缩总结

- **启动时检查**: 服务启动时检查并补全未总结的记录

## Phase 9: 记忆系统升级 - 多级总结

### 概述

将记忆系统从单级日级总结扩展为四级分层架构，支持递进式记忆压缩。

### 技术实现

- **周级总结**: `compress_to_weekly` 方法，将日级总结压缩为周级总结
- **月级总结**: `compress_to_monthly` 方法，将周级总结压缩为月级总结
- **年级总结**: `compress_to_yearly` 方法，将月级总结压缩为年级总结
- **递进式压缩逻辑**: 日→周→月→年的层级递进，每层使用上一层的结果
- **保留策略**:
  - L1 日级: 保留 14 天
  - L2 周级: 保留 8 周
  - L3 月级: 保留 12 个月
  - L4 年级: 保留 100 年
- **时间分区**: ChromaDB 按周（W14）、月（202603）、年（2026）分区存储

### 新增目录结构

- `summary_L2_weekly/` 周级总结向量库
- `summary_L3_monthly/` 月级总结向量库
- `summary_L4_yearly/` 年级总结向量库

## Phase 11: 深度回忆功能

### 概述

实现系统的核心特色功能——深度回忆，让角色能够真正"记住"过去的对话。

### 技术实现

- **三种回忆模式**:
  - `off`: 不进行深度回忆，仅使用短期记忆
  - `normal`: 从分层总结库（L1-L4）检索记忆
  - `enhanced`: 从最近半年的原始记录库检索
- **时间路由检索**: `retrieve_with_time_routing` 方法，根据时间范围智能选择检索来源
- **原始记录检索**: `retrieve_from_raw_records` 从 ChromaDB 原始记录中检索
- **自动意图检测**: 检测用户输入中的回忆关键词（"你还记得...吗"、"仔细回忆"、"很久以前"等）
- **结果去重**: 多源检索结果的合并与去重处理
- **时间标签标注**: 检索结果标注时间标签（如 [数日前的模糊回忆]）

### 新增功能

- 回忆模式状态管理（按角色保存）
- 回忆按钮循环切换（关→正常→增强→关）
- 自动意图检测关键词列表

## Phase 12: LLM 智能总结

### 概述

引入基于大语言模型的智能总结算法，替代原有的非 LLM 总结方式。

### 技术实现

- **总结模型**: 使用 Qwen3.5-Flash，开启思考模式（enable_think=True）
- **思考预算**: thinking_budget=4096 tokens
- **四层专用 Prompt 模板**:
  - 日级: 突出重要事件和情感变化（200-400 字）
  - 周级: 提炼核心主题和重要发展（300-500 字）
  - 月级: 提炼核心事件和成长变化（400-600 字）
  - 年级: 提炼核心主题和重大变化（500-800 字）
- **回退算法**: LLM 总结失败时自动降级为关键词提取算法
- **优先级**: LLM 总结优先，非 LLM 算法作为兜底保障

### 新增/修改模块

- `vdb_tools/hierarchical_memory_db.py` 中的 LLM 总结逻辑
- 四层 Prompt 模板

## Phase 17: 安全退出机制

### 概述

实现服务的安全退出流程，确保数据完整性与资源正常释放。

### 技术实现

- **Shutdown API**: 提供 `/shutdown` HTTP 端点触发安全退出
- **会话安全关闭**: 遍历所有活跃 RoleplaySession 并执行关闭操作
- **记忆凝固**: 退出前触发完整的记忆压缩与归档流程
  - 总结所有未总结的记录

- **前端退出流程**: 用户点击"退出服务"→ 确认弹窗 → 调用 shutdown API → 3 秒后程序退出

## Phase 19: 输入框气泡功能

### 概述

优化输入框表现，解决输入内容超出一行后可读性差的问题。引入"气泡模式"以多行方式展示和编辑长文本输入。

### 技术实现

- **HTML 结构**:
  - 在输入框上方新增气泡容器（`#input-bubble`），内含多行 `textarea` 和收起按钮
  - 在原输入框内新增展开按钮容器（`#expand-wrapper`），内含展开按钮
  - 使用 SVG 箭头图标（`<svg>`）作为按钮图标
- **CSS 样式**:
  - 气泡容器：绝对定位在输入框上方，最大高度 33vh，超出滚动，带展开/收起动画
  - 气泡内 textarea：透明背景、无边框、支持多行编辑
  - 展开/收起按钮：小圆形（28x28px）、居中显示、hover 高亮效果
  - 原输入框激活状态：边框高亮（`border-color: var(--bg-l4)`）、阴影增强
  - 过渡动画：展开 `bubbleExpand`、收起 `bubbleCollapse`（0.2s ease-out）
- **JavaScript 交互逻辑**:
  - `expandBubble()`: 展开气泡、复制内容、隐藏展开按钮、输入框加激活样式
  - `collapseBubble()`: 收起气泡、复制内容、显示展开按钮、输入框恢复默认
  - `syncBubbleContent()`: 气泡与原输入框双向实时同步
  - `updateExpandButtonVisibility()`: 输入内容超出一行时自动显示展开按钮
  - `isInputOverflowing()`: 检测输入内容是否超出单行（通过隐藏 div 模拟计算）
  - `resetBubbleState()`: 切换角色/对话时重置气泡状态
  - 发送消息后自动收起气泡并清空输入框
  - 气泡模式下 Enter 键仍可发送消息
